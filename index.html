01 Four agents, one agreed decision

Each agent owns one decision and runs a Perception, Reasoning, Action loop with an added Consent stage. A Consent Ledger picks one final action from their proposals before anything reaches the learner.

ZPD Scaffolding Agent Q-learning

Reads mastery, fatigue, and recent error rate, then picks how much help to give, either independent work, a partial hint, or a full worked example.

Consent and Trust Agent accept / reject

Asks the student to accept or reject every proposed change. A refusal is not wasted. It updates the trust score that shapes what comes next.

Overload Prediction Agent one step ahead

Forecasts overload for the next session from recent behaviour, and triggers a break before it happens.

Teacher Co-Pilot Agent human in the loop

Writes a plain rationale for each decision and flags learners whose trust, acceptance rate, or overload trend needs a teacher's attention.

04 Evaluation parameters

Four checks beyond the headline metrics, each reported honestly, including where the framework still falls short.

Significance

Not a lucky seed

p < 0.001

Paired t-tests over 240 observations confirm all three headline gains over the rule-based baseline.

Fairness

Shared across sub-types

0.024 spread

Final mastery spans just 0.975 to 0.999 across six SLD sub-types. Reward and overload burden are a bit worse for the SLD+ADHD Comorbid and Multi-SLD Comorbid groups, the most severely affected profiles.

Efficiency

Reaches mastery sooner

15.55 vs 24.65

Sessions to first reach mastery 0.6, about 37% faster than the rule-based baseline. Push-only is fastest at 12.85 because it never pauses to ask.

Lead time

Modest early warning

0.56 sessions

Across 1,126 overload events, 26.2% get at least one session of advance warning and the rest are caught only at the event. This is the clearest target for future work.

05 Architecture

Six parts once the persistent data store is counted move a request from the interface to one agreed, consent-checked change. The data store is read by every layer (dashed arrows in the diagram) and written only by the Consent Ledger (solid arrow).

L1: Interface
Multimodal student and teacher input and output (voice, text, touch)
L2: LLM interpretation
Figures out what is being asked (designed, not built in the reference code)
L3: MCP routing
Sends the request to the right agent
L4: Multi-agent
The four agents, each running its own consent-aware loop, output 4 candidate actions
L5: Consent Ledger
Picks one final, consent-checked action before anything reaches the learner
Data Store
IEP/LMS/behavioural record, read by every layer, written only by the Consent Ledger
priority order  IEP and safety  >  student consent  >  pedagogy  >  nudges
No LLM is needed to run it. The four built agents talk to each other with direct function calls on numeric data such as mastery, error rate, and timestamps. The LLM decision layer is part of the design for free text and voice input, and is listed as future work.
